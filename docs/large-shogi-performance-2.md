# 天竺大将棋・大局将棋の合法手生成高速化 第2期

完了。全14ルールの互換性・Chrome・Native32ルールと実WASMの性能回帰を検証済み。

## 実装

- 既知の移動先は、関係する移動成分と障害物だけを調べ、移動先Vecを作らない。
- 21語の広いビット集合はその場で更新する。4語以下は従来の値更新を保つ。
- 大局将棋だけ王駒数を差分管理し、捕獲・成り・取り消しで更新する。
- 生成済みの経路・貫通・成り先・早期終了と手番開始時の効果情報を、実着手にも再利用する。所有者・単調増加する世代・局面キー・pendingが一致した場合だけ使用する。
- キャッシュは再帰中の祖先を含め4 MiB以内。有限件数・途中キャンセルの結果を全件として保存しない。実棋譜に候補配列を保持せず、公開JSON・指し手・TTには内部ヒントを含めない。
- 移動先は小さいリストでは線形検索し、32件以上で盤面サイズの索引を使う。禁止マスと四天王の移動の集合にはビット集合を使う。
- 大局の単発・非貫通・列内枚数制約なしの移動は、候補列挙時の盤面変更・復元を省く。実際のperft着手・復元は葉まで行う。
- 天竺大は火鬼・四天王の種類・色・位置・在場順が不変なら、手番開始時の焼却範囲を使う。既存の未焼却駒と到着駒の色を再評価し、作用駒が変われば従来処理へ戻る。

探索の順序・評価・枝刈り・公開FNV/履歴ハッシュは維持する。

## 再現手順

比較の開始コードは790422b、最終のエンジンコードは521ebca（実装は5e5a85fと同一）。
依存は第1期の固定したCargo.lockを引き継ぐ。固定入力の葉数は再校正せずに比較する。
次のように**同じパス**の専用checkoutを前後のコードへ切り替えて計測する。

```sh
git worktree add --detach target/perft-reproduce 790422b
cp plans/historical-shogi-performance/inputs/dependency-Cargo.lock target/perft-reproduce/Cargo.lock
python3 scripts/perft-position-benchmark.py --engine-dir target/perft-reproduce \
  --positions plans/historical-shogi-performance-2/inputs/positions.json \
  --output target/phase2-before.json
git -C target/perft-reproduce switch --detach 521ebca
python3 scripts/perft-position-benchmark.py --engine-dir target/perft-reproduce \
  --positions plans/historical-shogi-performance-2/inputs/positions.json \
  --compare target/phase2-before.json --output target/phase2-after.json
```

CPU・コンパイラ・依存ロック・engineDirectory・ハーネス・入力のSHAが一致しなければ測定器が比較を拒否する。
3サンプルの最大/最小の幅が5%を超えた場合は再測定し、5%以上の低下は再現性と適用範囲を検討する。
実行中には別ビルド・参照照合・ブラウザー試験を重ねない。
32ルールの初期局面は `scripts/perft-benchmark.py` を使用し、同じ専用checkoutで前後を比較する。

## 処理量の診断

隔離した診断版の初期perft(2)では、天竺大の手番開始時の作用駒の導出が
17,491回から133回へ減った。両ルールとも、生成済みの手の実着手では
移動先の再判定を呼ばず、保持した経路メタデータを使っている。
ビット集合の更新も、大局のset_cellにあった168バイトのmemcpy呼出し6回を削減した。

| 初期perft(2) | 前の確保回数 | 後の確保回数 | 前の要求バイト累計 | 後の要求バイト累計 |
| --- | ---: | ---: | ---: | ---: |
| 天竺大将棋 | 200,256 | 148,696 | 9,234,824 | 7,878,840 |
| 大局将棋 | 1,250,355 | 1,162,336 | 135,982,720 | 139,801,132 |

大局では生成情報を保持する分、要求バイト累計は約2.8%増えたが、
コピー・再判定を減らして速度を改善した。これはalloc/reallocの累計要求量で、
同時に生存するメモリやWASM線形メモリの最大値とは異なる。
キャッシュの保持量には別に4 MiBの上限を設け、配布物の通常探索でもメモリを検査する。
診断の包含タイマーは重なり、コード配置にも影響するため、割合を足し合わせたり
通常版のNPSとして扱ったりしない。
