# 追加28ルールのNPS改善

[前回の計測](next-rules-perft.md)（`276379a`）で安南比3.9〜13.4%だった汎用ClassicalGame基盤の
28ルールを、プロファイルに基づいて高速化した。計測ソースは `0711768`。
計測条件・手順は前回と同じ（初期局面perft(3)、CPU 2固定、3秒×3試行の中央値、安南を前・中・後に計測）。

## 結果

安南の基準は **9,384,147 NPS**（前回9,413,464、差0.3%）。競合による除外・再測定は0、
3試行のばらつきは最大3.07%。perft(1..3)は29種とも前回と一致した。

- 王手のある23種は約36万〜127万NPSから **約346万〜457万NPS**（安南比37〜49%）になった。
  倍率は3.6〜10.5倍。取る一手・飛車・角は9.8〜10.5倍。
- 王手放置可の5種（どうぶつ、ざりかに2種、八方桂2種）は1.4〜1.9倍。
  どうぶつ・ざりかに2種は安南より速い。

## プロファイルで分かったこと

perfはこの環境の権限（`perf_event_paranoid=4`）で使えなかったため、
gdbを繰り返しattachしてスタックを採るサンプリングで測った（1回120〜200サンプル）。

不成将棋の当初の内訳は、合法性判定の王手検査（core `attacked`）が77%。
候補手ごとに局面をcloneし、全マスを走査して敵駒ごとに行き先Vecを作っていた。
malloc/freeが約20%。取る一手は、取る手の義務の判定を候補手ごとに再計算していた。
飛車・角は走り駒ばかりで、この全走査の負担が最も大きかった。

途中で `Position::index` が `.ok_or("...".into())` のため、
成功時も毎回エラー用Stringを確保していることも見つかった（これだけで約1.3倍）。

## 変更点

- 王手検査をroyalごとの直接判定にした。Vecを作らず、取れない駒の規則とcapture supportは保持。
- 局面ごとに1回、自玉への王手の有無（capture supportを無視した幾何的な利き）と
  「玉と敵の走り駒の間にある唯一の自駒」を求める。王手されていなければ、
  - 非royalの移動は、空いたマスがピン候補（または取った敵駒のマス）のときだけ、
    玉からそのマスの延長線上を調べる。打つ手は利きを遮るだけなので調べない。
  - royalの移動は、そのroyalを盤から除いた敵の利きマップを局面ごとに1回作って引く。
  - capture support系（Patrol/Lortap）は幾何的な判定を上位集合として使い、
    該当したときだけ支持条件込みで厳密に判定する。
  - それ以外（王手中、royalの成りなど）は従来どおり全判定。
- 候補手は局面ごとに1つの作業用コピーで指して戻す。履歴はpopした局面の確保領域を再利用する。
- 取る一手の義務を局面ごとに1回だけ計算する。
- 指し手のソートを `sort_unstable` にした（直後のdedupで等しい手は1つになるので結果は同じ）。
- 28ルールでroyal数のキャッシュ（既存の `CACHE_ROYALS`）を有効にした。

和将棋・大将棋など他のClassicalGame系ルールも同じコードを通るが、今回NPSは測っていない。

## 既存の無限に近い計算の修正

王手放置可で打ち歩詰めを禁じる八方桂・相八方桂では、王手の逃れを探すとき全合法手を先に検証していた。
打ち歩の検証がまた相手の逃れ探索を呼ぶため、局面によっては計算が指数的に膨らむ。
`276379a` でも、固定シードの対局で `moves()` が15秒以上返らない局面が24局中3局あった。
逃れになるかを先に調べ、逃れになる手だけ合法性を検証し、最初の1手で打ち切るようにした。
合否の意味は変えていない。上の3局も今回は完了し、ベースラインが完了した21局は結果が一致した。

## 正しさの確認

- 29種のperft(1..3)が前回と一致（計測スクリプトのassert）。
- 新テスト `selected_tests`（28ルールそれぞれのfeatureで実行）:
  記録済みperft(1..3)と、固定シードの12局×240手の対局。
  テストビルドでは、高速判定の各結果をcoreの `attacked` と、旧来のコピー方式の合法性判定と比較する。
  開き王手・中間マスの取り・capture support・玉の利きマップの各分岐は、
  わざと壊すとこのテストが失敗することを確認した。
- 公開APIだけで動く対局ドライバーで、276379aと今回の全局面の合法手リスト・勝敗のハッシュを比較。
  28ルール×24局×最大240手で差分0（ベースラインが15秒で終わらない八方桂2種の各3局は除く）。
  [記録](../plans/next-rule-groups/perft/20261127-nps/walk-comparison.log)。
- `haitaka` のライブラリテスト全件を不成将棋・和将棋・大将棋・禽将棋・平安大将棋・安南の各featureで実行し成功。
  ワークスペース全体のcheckも成功。

二玉将棋で「玉がもう1枚の玉の盾になっている」ときの分岐は、盾の玉自体が王手されるため通常は全判定に回る。
駒ごとに取れる/取れないが異なるルールでだけ到達する防御的な分岐で、テストでは到達を確認できていない。

## 再現

```sh
python3 scripts/benchmark-next-rules.py prepare --output target/next-perft-nps
python3 scripts/benchmark-next-rules.py run --output target/next-perft-nps --cpu 2
```

（`walkcmp.sh` のパスは作業時の一時ディレクトリ）。
