## 計測条件と負荷の確認

- Intel Core i7-6700、native release、Rust 1.98.1。opt-level=3、codegen-units=1、LTO=fat。
- 全て同じCPU 2に固定し1スレッド。SMTの対になるCPUは6。
- ウォームアップ1回を除外し、各試行3秒以上、各ルール3試行の中央値。
- 葉数/秒。最終手も実際に適用する。bulk counting、TT、評価器、探索の枝刈りは使わない。
  初期局面のJSON/SFENの準備・パースとビルドは持ち時間外。
  獅子の複数段移動は、完了した1ターンを1手として数える。
- 全バイナリのビルド・回帰テストを先に終えてから測定。計測中に自分のビルド・テストは動かしていない。
- ユーザーの別作業を確認するため、開始前にtopとプロセス一覧を調査。
  計測直前は3秒間の実CPU負荷が全体で0.057論理コア相当。
  各試行のtop・loadavgと、実行中のホスト全体のCPU時間を記録した。
- 計測中の総CPU負荷は1.02〜1.10論理コア相当で、ほぼ計測プロセス1本分。
  競合判定（1.5コア超）による除外は0、5%超のばらつきによる再測定も0。
  全ルールの3試行の範囲は最大3.75%。安南9試行全体の範囲は1.21%。
- 安南の各測定群の中央値は9,438,278 / 9,381,797 / 9,435,226 NPS。
  測定日時は2026-11-26 21:13〜21:18 JST。

## 正しさと比較の範囲

追加28種のperft(1..2)は、コミット済み将棋ったーcoreの独立した完了手生成で全て一致。
coreは `b337fafa2efcf7cd51d3a4da29d79c2691d93720` のスナップショットを使い、
他の作業ディレクトリの未コミット変更を含めていない。
安南のperft(1..3)は既知の28 / 784 / 21,718と一致。
各計測中も繰り返しごとのperft(3)が同じ値であることをassertしている。
perft(3)について28種全てを独立coreで全列挙する検証は行っていない。

追加ルール基盤の回帰34件が成功（別に1件ignored）。安南の盤・指し手生成35件も成功。
これらと独立coreの28件、29バイナリのビルドを確認した。
変更していない長時間DFPNテストの全件実行は対象から除外した。

28種は汎用のClassicalGame/JSON基盤、安南は専用bitboardのBoard基盤を使う。
JSONパース時間は除いたが、内部の局面表現・合法手生成・局面更新の違いは速度比に含まれる。
各ルール固有の盤面・初期配置・分岐数も反映されるため、この比率を中盤局面や探索NPS、
WASM・ブラウザーでの速度比へそのまま当てはめることはできない。
リベース前との同条件NPS比較は実施していないため、今回の数値から高速化率は主張しない。

今回速かった5種は、いずれも `ClassicalRule::CHECK=false`（自玉の王手放置を許す）という共通点がある。
これはコード上の対応関係であり、個別処理の寄与率をプロファイルで測定した結果ではない。

## 再現と原本

[CSV](../plans/next-rule-groups/perft/20261126/summary.csv) /
[全試行・条件・ハッシュ監査](../plans/next-rule-groups/perft/20261126/)。
依存バージョンを揃える場合は保存したworkspace-Cargo.lockを作業先のCargo.lockとして使う。
ソースをcommitした状態で、新しい保存先を指定して実行する。

```sh
cp plans/next-rule-groups/perft/20261126/workspace-Cargo.lock Cargo.lock
# 先にtop等で他の作業を確認。ビルドは2ジョブに制限。
python3 scripts/benchmark-next-rules.py prepare --output target/next-perft-new
# 全ビルド・テスト完了後、再びtopで他の高負荷処理がないことを確認。
python3 scripts/benchmark-next-rules.py run --output target/next-perft-new --cpu 2
# 保存したデータだけで再集計する（バイナリ不要）。
python3 scripts/benchmark-next-rules.py summarize \
  --output plans/next-rule-groups/perft/20261126
```

独立coreのドライバーは原本の `drivers/core-perft-reference.test.ts` に保存。
上記coreコミットの `packages/core`、`packages/ai`、`app/common`、`app/utils`、
`app/engines`、`vitest.config.ts`、`package.json` を別ディレクトリに展開し、
ドライバーを `app/nextPerftReference.test.ts` に置く。既存の対応するnode_modulesを使い、
そのディレクトリで `vitest run app/nextPerftReference.test.ts --maxWorkers=1 --no-file-parallelism` を実行する。
既存の完了手アダプターを介し、獅子の2段移動・先手後手の向きも揃える。

生成済みWASMの更新・ブラウザーでの性能比較は今回の対象に含めていない。
