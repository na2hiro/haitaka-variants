## 確認済みの原因と改善の仮説

基準コード: `e7ab6efc40e8838d62185e6a69d96a3ad28041e8`。
CPU: Core i7-6700、Native Release、CPU 7固定・1スレッド。
[32ルールのperft生データ](baseline/perft.json) / [表](baseline/perft.md) /
[診断計時](baseline/profile.json) / [原因](baseline/profile.md)。
診断はコピーしたソースに計時を追加した1.5秒以上・1回の概算。包含区間を合計しない。
診断時の全8ルールのperft葉数は通常版の測定と一致した。
[計時追加パッチ](baseline/profile-instrumentation.patch)は基準コードのコピーへだけ適用する。
通常版NPSは計時器を入れず3秒以上×3回の中央値で測っている。

| 対象 | 時間割合 | 仮定した局所高速化 | perft全体の試算 |
| --- | ---: | --- | --- |
| 和将棋の王手検査 | 80.5% | 5〜10倍 | 2.8〜3.6倍 |
| 平安大の王手検査 | 74.9% | 5〜10倍 | 2.5〜3.1倍 |
| 大大の全盤ハッシュ | 38.7% | 5〜20倍 | 1.45〜1.58倍 |
| 摩訶大大の全盤ハッシュ | 49.9% | 5〜20倍 | 1.66〜1.90倍 |
| 泰将棋の全盤ハッシュ | 61.3% | 5〜20倍 | 1.96〜2.40倍 |
| 大局の全盤ハッシュ | 57.4% | 5〜20倍 | 1.85〜2.20倍 |
| 天竺大の終了時効果 | 49.4% | 2〜4倍 | 1.33〜1.59倍 |
| 大型の経路再生成 | 内訳未分離 | 再生成の大部分を省く | 暫定1.05〜1.20倍 |
| 大将棋のコピー等 | 削減可能分は未分離 | 差分適用と領域再利用 | 暫定1.15〜1.35倍 |

試算は `1 / (1 - f + f / k)`。fは対象時間割合、kは仮定した局所倍率。
局所倍率は実測でも保証でもない。段階の採用前に実測へ置き換える。
段階間で同じ仕事を減らす場合があり、表の倍率をそのまま掛けない。

## 共通の測定手順

永続化した測定器は[scripts/perft-benchmark.py](../../scripts/perft-benchmark.py)。
一時Cargoプロジェクトとバイナリは`target/perft-benchmark`に置き、本体は書き換えない。
ルール別の深さと期待葉数はbaseline/perft.jsonから固定する。高速化後も勝手に深さを変えない。

```sh
# 第1段階: 実装前と実装後で同じ条件を使う
python3 scripts/perft-benchmark.py --rules washogi heian-dai daishogi --output target/perft-before-01.json
python3 scripts/perft-benchmark.py --rules washogi heian-dai daishogi --compare target/perft-before-01.json --output target/perft-after-01.json
# 最終: 32ルールを順番に測る
python3 scripts/perft-benchmark.py --output target/perft-final.json
```

各ルールをウォームアップし、CPU固定・1スレッド・Release・最低3秒×3回で測る。
葉まで着手を適用・復元し、末端一括カウント・置換表・評価・枝刈りを使わない。
NPSは葉ノード/秒で、検索時のNPSとは区別する。
ビルドはすべて終えてから測定し、測定中に参照照合・別ビルド・ブラウザテストを走らせない。
最低時間に達するまで同じperftを反復し、反復数・秒数・全サンプルを残す。

葉数不一致は即失敗。サンプル最大/最小NPS差が5%超なら負荷・温度・CPU設定を調べ、再測定する。
対象ルールの中央値+10%以上を初期採用目標とする。共通処理変更で非対象が5%以上低下したら
実装前後を交互に追加測定し、再現する低下は原因を解消するか変更を狭める。
32ルールの異なる深さのNPSを、同じ仕事量の絶対比較として扱わない。
初期局面だけへの最適化を避け、固定seedの途中局面・連続移動中・特殊効果局面も第5段階の手順で測る。
