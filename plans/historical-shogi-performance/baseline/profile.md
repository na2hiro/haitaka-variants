# 古将棋perftの遅さの切り分け

元コードをtarget内へコピーして計時を追加。本体は変更していない。CPU7・Release・各1.5秒以上。計時追加の影響がある概算で、区間は包含関係があるため合算しない。元のperft葉数と全8件一致。

| ルール | 主な測定区間 | perft全体に対する時間 |
| --- | --- | ---: |
| 和将棋 | 候補手ごとの王手放置検査 | 80.5% |
| 平安大将棋 | 候補手ごとの王手放置検査 | 74.9% |
| 大将棋 | 候補手検証用の盤面コピー・適用 | 23.2% |
| 天竺大将棋 | 手番終了時効果 | 49.4% |
| 大大将棋 | 全盤ハッシュ再計算 | 38.7% |
| 摩訶大大将棋 | 全盤ハッシュ再計算 | 49.9% |
| 泰将棋 | 全盤ハッシュ再計算 | 61.3% |
| 大局将棋 | 全盤ハッシュ再計算 | 57.4% |

原因: 和・平安大はCHECK=trueで候補手ごとに相手の利きを再生成。大将棋はCHECK=falseなので省略。天竺大は火鬼・四天王等の効果を候補列挙と実着手で計算。大型バックエンドは実着手時に移動先を再生成し、全盤の駒ID文字列をFNVでハッシュし直す。大将棋のclassicalバックエンドはperft実着手ごとのこのハッシュ計算を行わない。

改善候補: (1) 対象の王マスへの攻撃有無を直接調べる。全相手駒の全移動先Vecを作らない。(2) 探索用ハッシュを差分更新し、外部の安定ハッシュは必要時に計算。(3) 凍結・火鬼情報を局面または手番単位で共有し、検証済みの経路情報を実着手で再利用。(4) 一時Vec・盤面コピーを差分適用へ置き換える。

詳細: analysis.json。計時器: haitaka/src/speed_probe.rs、実行手順: run.py（すべてこのtarget/perft-profile以下）。
