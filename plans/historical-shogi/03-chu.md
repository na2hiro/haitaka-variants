# 第3段階: 中将棋の大盤と獅子の完了した1手に対応する

作成日: 2026-11-07。状態: 完了。
依存: [小将棋](02-sho.md)の拡張駒・王相当の集合・JSON API。
次段: [その他の古将棋](04-other-classical.md)。

## 対象と目標

| ルールID | Cargo feature / package ruleset | 盤 | ビット盤 |
| ---: | --- | --- | --- |
| 48 | `chushogi` | 12×12 | `MultiBitBoard<3, 144>` |

参照するのは `chushogi.ts`、駒定義、Shishi捕獲制御、Chu成り、手番継続と棋譜の処理。
玉・太子、王手放置を許す判定、持ち駒不使用を前段から継承し、中将棋のAI対局を完成させる。

## 実装のまとまり

### 1. 大盤を実際のBoardと探索へ接続する

固定長ビット盤の型だけでなく、盤面、色別占有、駒配置、利き、ハッシュ、合法手生成、
局面適用、評価、探索、置換表が144マスで動くようにする。未使用bitは常に0とする。

方向別の占有走査を使い、大盤のMagic表や全マス対の巨大な利き表を作らない。
`u64/u128` の直接演算や8/9/81の固定値が残る箇所を監査する。
移動が必ず単純な走り駒とは限らないため、駒定義から跳躍・有限歩数・連続移動を区別する。

### 2. 指し手を「完了した1手」として表現する

通常移動に加え、獅子の二段階の移動、途中と最後の捕獲、居食い、元のマスへの帰還、
合法に途中で終了する選択を区別する。必要なパス・終了操作は参照実装どおりに扱う。

- 経路と成りの選択を持つ指し手を生成し、合法性を途中の盤面更新も含めて検証する。
- 探索深さ・手番・千日手履歴は、経路全体が完了したときに1回進める。
- 同じ移動元と移動先でも途中の捕獲が異なる手を区別する。
- 移動元へ戻る手を「指し手なし」と混同しない。現行2座標codecの同一座標拒否を使わない。
- 置換表の指し手、並べ替え、PV、最善手の再適用で経路を失わない新しい符号化を用意する。

### 3. 獅子取りと成りを実装する

足のある獅子、隣接する獅子、獅子かげの足、付け喰い、先獅子を参照実装と照合する。
複数移動の途中盤面だけでは判断できない条件は、手の開始時点の情報を使う。
直前の獅子取りなど次の合法手に影響する状態は、局面の一部として保持・ハッシュ化する。

成りは敵陣4段のChu方式とし、単純な敵陣出入り判定を流用しない。
不成での侵入、再侵入、敵陣内の捕獲、捕獲しながらの退出、歩香の最奥段での成り、
行き所のない駒の扱いを個別に検証する。手の途中で成りを確定しない。

### 4. 探索と外部連携を仕上げる

合法性に影響する状態を含む局面ハッシュを使う。同じ駒配置でも先獅子等の状態が違えば
同一局面と扱わない。完了した1手を単位に反復深化と時間・ノード予算を使う。
各途中段階でも停止要求を確認し、予算超過やキャンセル時に部分的な指し手を返さない。

手作り評価に新駒を加える。静止探索の捕獲の価値には途中捕獲も反映する。
通常の王手による枝刈り・詰み探索を無条件に使わない。

JSON APIへ経路と必要なルール状態を追加し、将棋ったーの連続移動・終了操作へ変換する。
その場で全経路を適用できない場合は、未完了経路を局面に結び付けて保持し、途中の画面操作で
再探索や別の手を混ぜない。待った・再開・対局切替では古い経路を破棄する。

## 検証と完了条件

- 獅子の単一移動、跳躍、二段移動、二枚取り、居食い、途中終了を固定局面で照合する。
- 先獅子・付け喰い・影の利きと、合法／非合法が分かれる局面の組を作る。
- 全駒の移動・成り、王相当の捕獲、ステイルメイト負けを検証する。
- 63/64、127/128、143のマス、盤端・角・paddingで利きとハッシュを確認する。
- 経路・ルール状態のJSON往復と置換表の往復、通常適用と再計算の一致を確認する。
- 比較用の将棋ったー側も「完了した1手」の集合を列挙する。途中操作の数を合法手数にしない。
- 固定特殊局面に加え128局面以上で、合法手・全捕獲・最終局面・手番・結果を比較する。
- Nativeと実WASMで低予算停止・キャンセル・途中状態からの復元を確認する。
- ブラウザで獅子の連続移動を含むAI対局、待った、途中局面からの再開、終局を確認する。
- 前段と既存ルールの回帰を通し、WASMのサイズ・メモリ・応答時間を記録して完了とする。

## 着手時の追加調査

獅子取り規定のために棋譜から参照している情報を列挙し、必要十分な状態へ切り出す。
参照実装の連続移動・パス・成り確定の順序を、表示上の操作と完了した1手に分けて記録する。
成り元の識別など、同じ動きの駒でも区別が必要な状態も確認する。

## 採用仕様の追加記録

- 中将棋の39駒IDは成り元を保ち、同じ動きでも別IDを維持する。
- JSON v2は完了した1手の `from` と1～2個の着地点 `path` を保存する。
  `history` は開始局面と完了経路列。途中の一段目は `pending` として開始局面に結び付け、
  候補をその一段目からの完了手に限定する。探索深さ・千日手は完了後に1回だけ進める。
- 先獅子は直前の操作で「獅子以外がbl/dhを捕獲したか」の真偽として切り出す。
  二段移動の途中でも更新し、獅子取りの足は参照元と同じ開始盤面／途中盤面を使い分ける。
- Chu成りは歩・香の最奥段でも任意。行き所のない生駒を許す。
- 参照元の候補手生成に、敵陣内の捕獲で可能な成りを漏らす問題を確認した。
  着手処理のChu成り条件と一致する候補を返すよう、参照元に固定テストを追加して修正する。
- 将棋ったー側の保存済み局面ハッシュの形式は維持し、千日手比較とAIキャッシュキーに
  先獅子の状態を追加して区別する。連続王手の判定では獅子の途中盤面を数えない。
  獅子以外による獅子取りの直後の配置が戻ってきても、その最初の配置は先獅子が
  解除された配置の反復回数へ混ぜない。固定棋譜で終局が1手早まる問題の回帰を確認した。
