# 中将棋の PVS・1 ply LMR 実験

判定の一覧は [README](README.md)。前半は手作り評価、最後の節は Minase NNUE での計測。

2026-11-22、手作り評価の release ビルド。3構成で同じ共通探索と中将棋のルールを使用した。計測したコードは `feat/handcrafted-eval-experiments`（`7f29506`）に載せた未コミットの実装。このブランチでは最新 main に移植し、既定ビルドと実験ビルドの探索結果が計測時から変わらないことを照合した（[README](README.md#移植後の照合)）。

## 固定深さ

各試行は新しい CLI プロセスで `go depth` を実行した。ノード数は JSON 探索の `states` で、主探索と静止探索を含む。各セルはスコア / ノード数。

| 局面 | 深さ | 基準 | PVS | PVS＋LMR | 短縮 / 再探索 |
|---|---:|---:|---:|---:|---:|
| start | 2 | 0 / 356 | 0 / 356 | 0 / 356 | 0 / 0 |
| start | 3 | 4 / 8,731 | 4 / 8,170 | 4 / 8,170 | 0 / 0 |
| balanced | 4 | 4 / 2,136 | 4 / 2,136 | 4 / 2,136 | 0 / 0 |
| balanced | 5 | 4 / 27,175 | 4 / 20,965 | 4 / 7,774 | 157 / 0 |
| lion | 3 | 2220 / 7,035 | 2220 / 7,035 | 2220 / 7,035 | 0 / 0 |
| lion | 4 | 2220 / 16,653 | 2220 / 16,440 | 2220 / 16,440 | 0 / 0 |
| promotion | 3 | 472 / 215 | 472 / 215 | 472 / 215 | 0 / 0 |
| promotion | 4 | 666 / 562 | 666 / 624 | 666 / 624 | 0 / 0 |

全8条件で PVS と基準のスコアが一致した。6駒の静かな局面の深さ5で、LMR は PVS の20,965ノードから7,774ノードへ約63%減らした。

## 100 ms の先後ペア対局

既存の中将棋選別局面8件を履歴付きのまま使用。各比較は16局、4ワーカー、対局上限120完了手、探索上限64。各比較で同じ局面を先後入れ替えで使った。並行して回帰テストのビルドと実行を行った。

| 比較 | 勝–敗–分 | 打切り | 平均完了深さ A / B |
|---|---:|---:|---:|
| PVS 対 基準 | 0–0–16 | 16 | 1.54 / 1.42 |
| PVS＋LMR 対 PVS | 5–1–10 | 10 | 1.24 / 1.21 |

PVS 対基準は全16局が打切り。LMR 対 PVS は62.5%で、ペア Elo は +88.7 ［95% CI −8.3〜+185.8］だった。
LMR 対 PVS では深さ4を完了した手は両者あわせて0手で、対局ログから短縮が発生した回数は確認できない。
打切りの多さと到達深さを考慮し、この対局条件での棋力差は判定保留とする。

## 再現

計測スクリプト、局面、シャードごとのコマンド、集計 JSON は [`receipts/chu-handcrafted/100ms/`](receipts/chu-handcrafted/100ms/) にある。棋譜はコミットしていない。
基準は `chushogi`、PVS は `chushogi,search-variant-experiments,search-pvs`、
PVS＋LMR は `chushogi,search-variant-experiments,search-lmr` でそれぞれ `cargo build --release -p haitaka_cli --features` を実行する。
各バイナリを同ディレクトリに `baseline`、`pvs`、`lmr` として保存し、既存 JSON 対局ツールを各シャードのコマンドで起動する。

## 1手1秒の先後ペア対局

## Minase v3 統合後の main（8630a75）での再計測

main `8630a75`（Minase v3 LayerStack と v2.6 MNUE の両方を読み込める）に、前回までの PVS・LMR の実験部分を移植した。差分は [`receipts/chu-minase/experiment.patch`](receipts/chu-minase/experiment.patch)。この計測用の移植では `search-variant-experiments` なしで PVS・LMR が有効になる。このブランチでは他のルールと同じく `search-variant-experiments` も必要にした。有効にしたときの探索結果は計測時と一致する（[README](README.md#移植後の照合)）。評価はすべて Minase NNUE で、手作り評価は使っていない。

- 条件：1手1秒、上限4096手（開始手順を含む）、前回の v3 対 v2.6 と同じ16開始局面で先後を入れ替えた。各比較32局。打ち切りを含む先後ペアは集計から外した（Minase と同じ扱い）。
- 計算機：mba（Apple M4）。高性能コア4つに合わせて4並列で動かし、CPU は固定していない（macOS には taskset がない）。
- 固定深さ：10局面 × 深さ3・4 × 2モデル（40条件）で、基準構成は既存 CLI と一致し、PVS のスコアも基準と一致した。mba でも、Linux とスコア・選択手・ノード数・探索統計が完全に一致した。
- 深さ4の主探索ノード（10局面合計）

- 200手で打ち切ると、各比較32局中27局が打ち切りになる。400手でも12〜20局が打ち切りになる。
- 前回、v3 ブランチを Linux で計測したときの v3 対 v2.6 は13勝19敗（40.6%）で、平均完了深さは2.61対2.71だった。今回は15勝16敗で、平均完了深さは3.42対3.35。
- 3比較とも信頼区間が0を含み、棋力差は判定保留とする。LMR はノード数を減らしたが、対局中の完了深さは伸びなかった。
- PVS・LMR の比較は v3 だけで行った。v3 対 v2.6 は両側とも基準探索。枝刈りの効き方はモデルで異なる（固定深さで LMR のノード削減は v2.6 が大きい）ため、ここから「枝刈りありでの v3 対 v2.6」は推定できない。
- 結果は [`receipts/chu-minase/`](receipts/chu-minase/)：`summary.json`（200・400・4096手での集計と側ごとの探索統計）、`bench.json`（固定深さ）、`manifest.json`（局面・モデルとバイナリのハッシュ）、`measure.py`（mba 版）、`measure-linux.py`（Linux で途中まで使った版）。棋譜（約88 MB）はコミットしていない。
